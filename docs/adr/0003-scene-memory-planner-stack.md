# Scene-Memory Planner Stack

Status: Accepted for staged implementation.

Add a top-level **Planner Stack** selector now, with `planner-current` as the default baseline planner family and `scene-memory-v1` as the first non-default planner family. This deliberately introduces a planner-family boundary above **Longitudinal Stack** instead of extending `LongitudinalStack`, because the destination is a planner architecture that starts with longitudinal authority and can later include lateral planner authority without redefining **Longitudinal Mode** or custom longitudinal-stack policy.

`scene-memory-v1` uses only volatile short-horizon **Scene Memory**: recent evidence freshness, confidence, eligibility, and continuity inside the active onroad cycle. The first milestone treats Scene Memory as a shadow snapshot over existing scene-like artifacts such as lead context, SCC evidence, planner candidates, speed/map state, and planner output; it does not reclassify those sources or change actuation. Later active behavior must respect **Longitudinal Mode** source boundaries, cannot replace or override **Longitudinal MPC** physical feasibility, and must fail closed after authority begins rather than silently falling back to baseline output. A normal cruise-settings **Planner Stack Setting** is accepted despite rollout risk, but active `scene-memory-v1` selection must be blocked by a **Planner Validation Gate** until unit, replay/Drive Lab, telemetry, and fail-closed checks prove the planner safe enough to select.

The destination is a full longitudinal planner rewrite around scene memory and explicit source confidence, but implementation starts with a legacy-equivalent boundary and shadow-memory milestone: selector, telemetry/schema, validation gate, UI setting, Scene Memory snapshot scaffolding, strict planner-current equivalence, and tests. This preserves debuggability and safety while creating the durable boundary needed for later active planner behavior.
